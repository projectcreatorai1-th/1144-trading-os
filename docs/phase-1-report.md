## 5. Data pipeline

RAW -> VALIDATE -> NORMALIZE -> QUALITY -> VERSION -> LINEAGE -> EVENT (docs/phase-1-data.md). Raw is immutable truth with sha-256 integrity; duplicates recorded, never overwritten; INVALID never flows downstream (fail closed with structured reasons + EVENT_REJECTED).

## 6. Time pipeline

Source-semantics-aware validation separating INVALID vs LATE vs STALE vs OUT_OF_ORDER; ordering monitor (expected/actual/difference); latency metrics with UNKNOWN-never-guessed semantics; anomaly marking without touching original timestamps (docs/phase-1-time.md).

## 7. Event pipeline

Registry-validated ingestion -> Event contract 1.1.0 -> causal validation -> append-only store -> bus publication; derived events (ACCEPTED/QUALITY_CHANGED/TIME_ANOMALY/REJECTED) preserve correlation/causation (docs/phase-1-events.md).

## 8. Data quality

15 structured rules DQ-001..DQ-015 with evidence; classification VALID/DEGRADED/STALE/INVALID/UNKNOWN; INVALID blocks downstream; UNKNOWN never valid (docs/data-quality.md).

## 9. Lineage

SOURCE -> RAW -> NORMALIZED -> EVENT chain per ingestion, walkable to the root, extensible to future stages (docs/data-lineage.md).

## 10. Versioning

data_version/schema_version/source_version preserved end-to-end; normalized corrections are new records (supersedes), never overwrites; contract changes all followed the Phase 0 procedure (typed history entries + correct bumps).

## 11. Event store

SQLite (stdlib) behind the EventStore port: append-only, transactional, restart-safe, dedup-key indexed, no deletion APIs (docs/event-store.md).

## 12. Event bus

EventBus port + deterministic in-process implementation: validation on publish, environment gate, structured subscriber-failure handling. Technology swappable without touching core.

## 13. Replay foundation

Read-only ReplayRunner (time range / type / correlation) gated to the REPLAY environment; marker events; LIVE routing impossible (docs/event-replay.md).

## 14. Recovery behavior (tested)

Duplicate ingestion, reprocessing the same input after restart, store write failures (structured StorageError), append-only rejection of duplicate event ids, and idempotent recovery (no duplicate canonical history) - all deterministic.

## 15. Security boundaries

No credentials anywhere (config/source registration/log contracts reject secret-like keys - SEC-001); sensitive source fields are redacted in logs and views while raw payloads stay untouched (irreversible transformation of raw data is impossible by design).

## 16. Performance measurements (local, developer machine - NOT production-scale)

See docs/phase-1-benchmark.md (generated by `python benchmarks/phase1_benchmark.py`): on this dev machine ~12 events/s through the full validation/quality/normalization/event/store/bus path; per-stage durations reported from latency reports; store count and type-query operations sub-millisecond. ## 23. Known limitations (documented, deliberate)

- Source registry and ordering/sequence monitors are in-memory per session (dedup and history are persisted; restart-safe where required - tested).
- Single-threaded execution; no concurrency claims (SECTION 44).
- No deletion/retention APIs (retention policy not yet versioned - SECTION 42).
- Replay is a read foundation, not a re-execution engine.
- Event bus is in-process; distributed transport is a later phase.
- Local benchmark only; no production-scale claims.
